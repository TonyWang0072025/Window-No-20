# 《20号窗台》设计基线

版本：V0.1 · 整理日期：2026-11-01（北京时间）

## 文档用途与依据

本稿用于建立项目 GitHub 文档基线，依据本次提供的第三阶段对话及检索到的本项目历史共识整理。不是原始聊天逐字稿，也不代表硬件或程序已经实现。尚未取得独立的既有设计文档原件；未核实细节标注为待核对，不补写为正式决定。

## 1. 产品定位

- 暂定名称：《20号窗台》。
- 基于 ESP32 的、有艺术感的桌面电子摆件，作为20岁生日礼物，需方便跨城邮寄，制作难度控制在中低水平。
- 核心组合：小猫电子宠物、专注计时器、独立星星瓶、低调的生日秘密信箱。
- 小猫无需喂养或强制照顾，不以必须学习才能获得陪伴为前提。
- 当前以像素小房间为视觉方向，角色和场景具体造型尚待第四阶段设计。
- 产品与技术选型应控制复杂度。先使用入门套件学习，再推进打板、外壳、配件与组装；计划另做一套自留。

## 2. 功能与交互

主界面呈现小猫生活的房间；专注、星星瓶、信箱是主要功能入口。

三个实体按钮已在历史设计中出现。从左至右“返回／切换／确认”、主界面高亮书桌／星星瓶／信箱、确认暂停或继续等操作，仅检索到历史助手摘要，完整按键映射与退出确认流程仍需对照第二阶段原始记录核实，不作为已完成的交互规格。

## 3. 小猫行为

### 已确认

- 在几个固定地点之间走动，不采用完全自由活动和寻路。
- 白天清醒为主，夜间睡眠概率提高，但仍可以醒来自由活动。
- 日常行为较丰富，包含走动、伸懒腰、清洁毛发等。
- 开始专注后，小猫前往书桌读书；专注自然完成时伸懒腰。

### 当前框架，数值待验证

- 持续状态：坐着、看窗外、睡觉；其间穿插眨眼、摆尾、舔爪、伸懒腰等短动作。
- 通过走动动画衔接位置变化，避免瞬间传送；尽量避免连续重复同一短动作。
- 暂定约3个活动地点，具体位置随房间美术决定。
- 持续时间、出现权重、动作间隔尚未锁定。此前几秒、几分钟的示例不是正式参数。
- 专注优先于日常行为；暂停期间的猫咪表现、提前结束后的过渡细节待补齐。

## 4. 昼夜与天气

### 昼夜

按 UTC+8 运行，仅保留两种场景：

| 模式 | 时间 |
| --- | --- |
| 白天 | 06:00—17:59 |
| 夜晚 | 18:00—次日05:59 |

清晨归入白天，黄昏归入夜晚。不再单独制作四时段。昼夜变化不自动改变屏幕亮度。

### 天气

白天开始、夜晚开始各抽取一次天气。原始确认的抽取概率：晴朗80%、多云10%、小雨9%、特殊天气1%。天气为虚构窗景，不要求对应现实。

特殊天气先制作流星：呈现整晚持续划落、流动的窗景，不只闪现一次。

待定边界：助手随后提出“流星仅夜晚参与抽取”，并建议白天改为81%／10%／9%；用户尚未明确批准这一概率调整。不能将其当作正式概率。白天抽中原1%特殊档的处理与夜间限定须在实现前确认。

设备重启保留当前时段天气、防止反复重抽，是此前助手提出的建议，未见单独明确确认；具体存储规则待补齐。

## 5. 专注与星星瓶（第三阶段已验收）

| 专注时长 | 自然完成奖励 |
| --- | --- |
| 15分钟 | 1颗星 |
| 20分钟 | 1颗星 |
| 30分钟 | 1颗星 |
| 45分钟 | 2颗星 |
| 60分钟 | 3颗星 |

- 倒计时自然走完才算完成。
- 允许无限时长暂停，暂停时停止倒计时。
- 提前结束不给星星。
- 自然完成时立即计入并保存奖励，不等待确认；完成提示后按确认返回主界面。
- 断电后保留已获得星星及重要记录；未完成专注不恢复。
- 星星不会消耗，也不解锁其他功能。
- 主界面不显示累计星星数，进入星星瓶页面才显示。
- 奖励是加权成果，不是专注轮数或总分钟数的等比例换算。

| 累计星星 | 瓶内视觉状态 |
| --- | --- |
| 0 | 空瓶 |
| 1—25 | 少量 |
| 26—50 | 中等 |
| 51及以上 | 满瓶 |

## 6. 首次开机与秘密信箱（第三阶段已验收）

- 首次开机播放小屋亮起、小猫登场和20岁生日祝福，停留至按确认。
- 欢迎动画仅自动播放一次，可从秘密信箱重看。
- 信箱包含3—5封简短小信，全部开放，可反复阅读；具体封数、文字尚未制作。
- 首次进入信箱有一次性特殊动画，后续直接进入选信界面。
- 欢迎动画与信箱首次动画分别保存记录，互不影响。
- 后续普通开机直接进入日常主界面。

## 7. 系统运行（第三阶段已验收）

| 项目 | 规则 |
| --- | --- |
| 声音 | 当前版本完全无声 |
| 昼夜亮度 | 不因白天或夜晚自动调整 |
| 无操作10分钟 | 降低屏幕亮度 |
| 累计无操作60分钟 | 熄屏 |
| 计时基准 | 均从上次有效操作起算，不是调暗后再等60分钟 |
| 专注相关界面 | 进行、暂停、结束确认及完成等待确认等界面始终保持正常亮度 |
| 返回日常主界面 | 重新开始计算闲置时间 |
| 熄屏首次按键 | 仅唤醒，不触发按钮原功能 |
| 低亮度比例 | 留待屏幕选型及实测确定 |

熄屏不要求主控停止运行；“只关闭屏幕、主控继续运行，不进入深度睡眠”是当前实现建议，具体方案待硬件阶段落实。

仅调暗时首次按键是否同时执行原功能、哪些操作算有效操作、首次动画和信件阅读是否受闲置熄屏影响，尚无完整规则，待补齐。

## 8. 进度与下一步

项目规划共有6个实操前的设计阶段，前3阶段已完成；第三阶段为功能规则设计，第四阶段为视觉与角色设计，尚未开始。

第四阶段已有推进顺序：小猫角色 → 房间场景 → 屏幕UI与动画 → 产品实体外观 → 产品设定画册规划。具体形象、布局、配色、材质都未确定。

第五阶段涉及硬件与时间同步方案，但完整阶段名称和第六阶段具体任务未从当前材料核实，不重新编造。六个设计阶段不含后续开发、调试、打板、外壳制作与组装。

产品完成后还需制作角色与房间设定图、角色多角度或多形态资料，并附名片大小的手写保修卡。

## 9. 实现前待解决清单

1. 核实第二阶段完整按键、菜单和退出确认规则。
2. 明确白天特殊天气概率的处理、流星是否严格限定夜晚。
3. 确定天气跨重启保存与离线跨时段规则。
4. 确定时间来源、首次校时及失去网络时的表现。
5. 选择屏幕、开发板、供电、按钮、存储、外壳；具体型号尚未锁定。
6. 测试屏幕调暗比例、唤醒以及动画效果。
7. 补齐有效操作定义、非专注页面休眠边界与调暗按键行为。
8. 确认各类数据保存时机与断电保护，避免奖励重复或丢失。
9. 核实完整六阶段原计划；继续第四阶段视觉设计。
