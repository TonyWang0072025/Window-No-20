# 《20号窗台》产品设计基线（GDD / PRD）

版本：V0.2｜共识整理截至：2026-11-03｜状态：**功能规范已基本确定，硬件方案进入验证；不是已完成成品**。

## 0. 规范与状态说明

本稿按用户历轮确认与旧版 V0.1 合并整理。**确认**=作者明确认可；**目标/候选**=工程方向尚需验证；**待定**=不得当作事实。对过时规则，以本稿及 docs/decision-log.md 的后续确认优先；保留历史于 Git。

## 1. 定位、边界与交付

- 名称：《20号窗台》 / Window No. 20。
- 定位：方便邮寄的桌面艺术电子摆件，是朋友间有趣而特别的20岁生日礼物；安静温暖、有一点轻童话氛围；小猫自然生活，不需要照顾或成长任务。
- 核心模块：日常小猫房间、书桌专注、星星瓶、秘密信箱、朴素挂钟与设备自身的昼夜天气。
- **专注不是猫咪活跃或收到信件的前提**；无惩罚，无任务式宠物喂养。第一版完全无声，没有额外传感器/联网依赖。
- 计划制造**两套**（赠送版与自留版）。交付主体设备、一本文图结合的彩色角色与房间设定画册、名片大小手写保修卡；后者可轻松幽默地提及后续升级/维修。
- 轻世界观（已认可）：一间不强调来历的小屋、温和橘猫、窗外昼夜和天气、收集专注时光的星星瓶、为新主人留下小信的信箱。具体故事正文与猫名字待制作。

## 2. 视觉与房间

- 正式目标屏幕：**白色单色 OLED，横向128×64像素，2.42英寸**；黑色背景，仅需显示文字/图形的像素点亮，其他关闭。参考模块有效画面约55×27.5mm；型号/接口需实物采购核实。
- 彩色方案C只用作**空间关系参考**，并非能直接缩小到128×64的生产资产。128×64要做适配重绘，保证小猫、书桌、瓶、信箱、时钟可认。
- 方案C：**左侧书桌、中央小台上的星星瓶、右上窗户、右下猫窝、左上低调秘密信箱**；墙面加入略大而朴素的时钟，不需钟周边装饰；尽量减少其余装饰拥挤。
- 小猫：略胖、圆脸、典型橘猫，**白胸口**；不穿衣、不拿书、不做拟人动作。黑白屏只需基本可爱可认，不要求颜色/胸口特征可见；完整彩色设定放进画册。
- 日常主要地点：猫窝（右下）、窗台（右侧）；专注时到左书桌。仅在窗右侧固定位置跳上/下，减少动画复杂度；走到固定地点而非复杂寻路。
- 基础姿态：猫窝休息/卷卧、窗台看景、书桌前腿自然搭在桌面且低头看摊开的书。最小动作：短距离走动、固定点跳上/下窗台或书桌、书页翻动、完成时伸懒腰。**已从第一版移除眨眼、舔毛和清洁毛发**。动作帧与权重尚未定。
- 日间清醒为主，夜间更容易睡；夜间也可走动。普通动画不应过于频繁；专注状态优先，覆盖日常活动。

## 3. 三个实体按键与房间导航

正面从左到右：**返回｜切换｜确认**。切换为单方向循环选项/数值，确认选中或执行，返回退出/取消；无长按强依赖。主房间**默认无高亮**，按切换首次高亮书桌，再星星瓶→秘密信箱→时钟→书桌循环；被高亮对象用浅色像素描边或小提示符号提示。无高亮时确认和返回无效；返回可取消高亮。

功能流程详细见 [交互文档](interaction-flows.md)，以各状态下的专用操作覆盖上述一般行为。

## 4. 专注计时器

### 4.1 设置与开始

- 高亮书桌确认进入选时页；简洁独立界面：文字“请选择专注时长”、大号预设数字、“确认后开始计时”；**删除“WINDOW NO.20”字样**。
- 预设：**15 / 20 / 30 / 45 / 60 分钟**；切换循环，确认开始，返回主房间。
- 开始后回到房间，小猫跳/移动到书桌，像普通猫一样自然坐姿看摊开书本，书页自动翻动。
- **倒计时数字悬浮在画面水平中部、稍偏上位置**，不得遮挡关键交互物件和小猫；具体坐标在128×64排版中验证。

### 4.2 进行、暂停、退出确认与完成

- 专注中右侧**确认**暂停/继续；暂停时计时和书页动作停止，显示**整屏纯黑背景＋“暂停”**，绝不叠在房间上；从暂停继续时返回房间。
- 正在专注或暂停时按返回进入**提前结束确认页**并冻结计时；在该确认页按确认=提前结束无星；按返回=回到之前的进行/暂停状态（继续前的原始状态）；切换无作用。此页文案/布局可工程化，但不得误结束。
- 专注期间切换键无作用。
- 倒计时只有**自然走完到00:00**才计入星星；暂停不算时间；提前退出、断电导致未完成，都不奖励。
- 达成时播放小猫伸懒腰的短动作（与立即转黑底完成页的衔接方式待确认）；完成页**黑底**、显示“**专注完成**”，不显示房间场景，停留直到按确认回主房间。
- 奖励在自然完成时**立即保存、且同次完成仅发一次**，不等用户确认。完成页是否同时显示“+N星”未最终明确，以主文案为准，不能擅自加复杂内容。

| 预设专注时间 | 自然完成奖励 |
| --- | --- |
| 15、20、30分钟 | 各+1星 |
| 45分钟 | +2星 |
| 60分钟 | +3星 |

## 5. 星星瓶

- 主房间瓶子小图标，**不直接显示星星数**。
- 高亮瓶→确认进入**纯黑背景**的全屏独立页面：只呈现放大的星星瓶与**准确累计星星数字**，不透出房间场景；返回回主房间；无其他必需按键操作。
- 0为空瓶，1–25少，26–50中，**51及以上满**。瓶中的可见星数是视觉分档，不必逐颗对应真实累计值。
- 星星**永不消耗**，不用于解锁宠物、信件或功能；跨断电保存。

## 6. 秘密信箱和首次欢迎

- 小信箱自然隐藏在房间，**不显示红点/未读提醒**；全部3–5封主题各异的小信初始即可阅读且可无限次回看：生日祝福、轻松幽默、猫咪视角、制作者寄语等方向仅为文本策划候选；正式信件内容尚未写。
- 高亮信箱→确认进入选信页；切换循环信件、确认阅读；阅读页返回选信页，选信页返回房间；阅读页其他按钮无功能。
- **第一次打开信箱**播放一次短暂仪式动画，另存一次性标记；之后进入选信页。可从信箱中重看欢迎生日动画。
- **首次开机欢迎**：房间亮起、猫登场、20岁祝福；祝福停留直到按确认才进房间；只自动出现一次，后续可在信箱主动重看。
- 欢迎已播记录、信箱首次记录、累计星星为**跨更换全部AA电池必须保留**的数据。正式持久化方案见硬件文档。

## 7. 昼夜与天气

- 按**设备自身的24小时制时钟**判断（目标按UTC+8北京时间手动设置；未校准不保证与现实同步）。
- 白天06:00–17:59；夜晚18:00–次日05:59。没有清晨、黄昏的单独场景。
- 每次进入新半天时段（06:00与18:00）抽一次虚构窗外天气，概率的原确认分配为**晴80% / 多云10% / 小雨9% / 特殊1%**。
- 稀有天气目前以**流星**为美术方向，视觉上要在选中的**整个夜间**偶发划过，不是只演一瞬；但**白天特殊1%如何处理、是否夜间专属以及日间概率是否改81/10/9**，尚未批准，第一轮不能私改。
- **上电天气初始化**：首次开机或完全断电更换电池后，设备时间从12:00开始，属于白天，应当**为本次启动时段初始化（抽取）一次白天天气**，使窗景立即正常运行；同一时段不因进入菜单、点亮屏幕、画面重绘而重复抽取。本规则**不解决**白天特殊1%天气的具体表现或概率调整；手动改时间与其他天气持久化边界仍待后续确认。
- 夜晚睡眠概率更高，仍可活动。**昼夜不会自动改变OLED亮度**，亮度由闲置规则控制。

## 8. 时钟（后续新增的正式功能）

- 房间墙上略大、简单朴素的小时钟，作为可切换/确认的**第四个可交互物件**，不是实体增加按钮（用户曾称新增“第五部分”功能）。
- 进入可查看设备时间，使用已有三键、24小时制逐位或逐项校准小时和分钟；具体微交互可按三键方案实现。
- **首次开机或完全断电后**，若无独立后备时钟，从**12:00**开始自行向前计时；不弹强制设置，不显示“--:--”，不停止昼夜与天气功能。
- 用户可按自己的喜好完全不校准；此时昼夜天气正常按设备时间变化，**不宣称当前时间是准确北京时间**。
- 校准之后按新的本机时间正常切换昼夜。设备持续供电及休眠时计时应推进；换电池后仍从12:00重启，不用旧时间冒充真实时间。
- 当前**不要求联网/NTP**，也未将独立电池后备RTC纳入必要配置。

## 9. 亮度、休眠及数据

- 第一版**完全无声**。
- 在日常非专注界面，最后有效操作后**累计10分钟调暗、累计60分钟熄屏**（不是在调暗后再等60分钟）。
- 在所有专注流程：进行、暂停、退出确认、完成待确认，屏幕持续正常亮度，暂停不限时。
- 熄屏后按任一实体键可唤醒，但**唤醒用的首次按下只唤醒不执行按钮本身功能**。
- 不以日间/夜间直接改变屏幕亮度。调暗比例、调暗后第一键行为、信件阅读是否闲置熄屏以及睡眠实现方式尚待实测/补充。
- 常态运作与深睡唤醒必须让设备时钟和专注逻辑符合产品规则；不可为了省电使屏幕在专注中自动熄灭。
- 存档至少包含：累计星星、首次生日欢迎完成标记、信箱首次仪式完成标记。对已完成奖星的断电中断，须避免重复发奖；具体存储/原子提交策略待设计并测试。

## 10. 实体方向与量产路线

- 正式屏幕：**2.42英寸128×64白色单色OLED**，128宽×64高、黑底亮点；参考显示区55.01×27.49mm、模块外形约61.5×39.5mm，最终依实际采购模块工程图。
- 最终主控候选已认可：**ESP32-C3-MINI-1模组＋定制小PCB**；现有普通ESP32＋0.96英寸OLED用于第一轮原型验证。
- 供电：优先**3节5号（AA）碱性干电池**、可靠的3.3V供电管理、可换电池；干电池仓前/后/底具体布置待机电协调。
- 续航**目标2–4周，理想约30天**，不是已证实结果。需要实际测量平均功耗、休眠/唤醒、OLED亮暗、按键和时间准确性。
- 外壳：**A2“小窗匣子”**——正面小窗/相框，完整、厚实、可独立稳立在桌面；**深色系**降低显脏程度，具体深色待选；屏幕向后倾斜**10°–15°**，正面下方三键。
- 采用3D打印制作，内置电池仓、屏幕、主控PCB；电池仓背部/底部未定；供电开关、编程接口和装配公差待结构阶段确定。
- PCB计划**嘉立创打样**，优先考虑适合的SMT工厂贴装，但成本、器件可贴性和供货未核实。
- 最终两套成品与附赠画册、手写保修卡；不在工程验证前锁定外壳体积与续航。

## 11. 阶段与当前进度

1. 产品定位与功能框架：**完成**。
2. 三键导航交互：**完成**，保留少数微交互边界待补充。
3. 完整功能规则：**基本完成**，天气/睡眠等有限边界待定。
4. 视觉角色与屏幕UI/实体外观/画册结构：**方向确定**，量产像素素材和完整画册尚未制作。
5. 硬件与结构方案：**已选方向，待原型测试**。
6. 总体验收与实施规划：**已形成初步测试与开发交接**，需迭代实测。

之后的实际开发顺序：当前ESP32套件基础功能原型 → 正式屏幕/软件 → ESP32-C3＋AA功耗原型 → 嘉立创PCB与3D打印 → 两套整机验收与礼物物料。
