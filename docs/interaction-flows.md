# 《20号窗台》交互/状态规范

版本 V0.2｜2026-11-03｜状态：**已确认主流程＋明确标注未决微细节**。所有实际屏幕均为128×64横屏逻辑画布；早期原型0.96英寸OLED只验证功能。

## 1. 按键语义

| 状态 | 左：返回 | 中：切换 | 右：确认 |
| --- | --- | --- | --- |
| 房间、无高亮 | 无动作 | 高亮书桌 | 无动作 |
| 房间、已有高亮 | 取消高亮 | 书桌→瓶→信箱→时钟→书桌 | 打开高亮物件 |
| 专注时长选择 | 回房间 | 15→20→30→45→60→15 | 开始专注 |
| 专注进行中 | 进入提前结束确认并冻结 | 无动作 | 暂停 |
| 专注暂停（黑屏文字） | 进入提前结束确认并冻结 | 无动作 | 继续 |
| 提前结束确认 | 返回此前进行/暂停状态 | 无动作 | 结束且**不加星** |
| 专注完成（黑屏文字） | 未定，默认不额外操作 | 无动作 | 返回房间 |
| 星星瓶详情 | 回房间 | 无动作 | 无动作 |
| 信箱选信 | 回房间 | 选下一封，循环 | 读所选信 |
| 信件阅读 | 回到选信页 | 无动作 | 无动作 |
| 时钟查看 | 回房间 | 可选“校准”控件/步骤 | 进入校准 |
| 时钟校准 | 退回上一位/取消 | 增加当前位（循环） | 确认当前位→下一位→保存 |
| 首次欢迎停留 | 默认不响应 | 默认不响应 | 完成欢迎，进入房间 |
| OLED已经熄屏 | **只唤醒** | **只唤醒** | **只唤醒** |

时钟查看页与编辑页“先按切换还是确认”以及最终保存/放弃的完整微状态可以在第一轮原型以可复核建议实现，不得增加物理按键或强制校时。

## 3. 专注状态图

~~~mermaid
stateDiagram-v2
    [*] --> Select: 选书桌
    Select --> Running: 确认预设
    Running --> Paused: 确认
    Paused --> Running: 确认
    Running --> ExitConfirm: 返回/记住Running
    Paused --> ExitConfirm: 返回/记住Paused
    ExitConfirm --> Running: 返回/此前为Running
    ExitConfirm --> Paused: 返回/此前为Paused
    ExitConfirm --> Abandoned: 确认/不奖励
    Running --> Completed: 时间自然归零/奖星写入一次
    Completed --> Home: 确认
    Abandoned --> Home
    Running --> Home: 完全断电/本次会话取消
    Paused --> Home: 完全断电/本次会话取消
~~~

**时间处理**：
- 使用单调计时（时间差累加）计算有效专注时间，暂停和退出确认不计入，不能依赖墙钟是否被校准。
- 动画耗时、主循环渲染延迟不能累积成过快/过慢倒计时。暂停无最长时间限制。
- 自然归零即奖星并保存，不等待确认；禁止在“完成页反复刷新”或“重启”时重复奖励。
- 在Running时呈现房间＋小猫书桌看书＋画面中上部悬浮大数字；Paused为**纯黑底＋暂停**；Completed为**纯黑底＋专注完成**。退出确认不得显示模糊不清的模态背景引发误触。
- 已确认自然完成时猫要伸懒腰，但完成页又要求纯黑背景。建议在转黑之前安排极短收尾动作；切换细节尚待产品最终确认，原型可暂以日志占位。

## 4. 星星瓶与信件

~~~mermaid
flowchart LR
    H[房间] -->|瓶/确认| J[星星瓶:大瓶+准确累计值]
    J -->|返回| H
    H -->|信箱/确认| F{是否首次进入}
    F -->|是| A[一次性信箱开启动画]
    A --> L[选信页]
    F -->|否| L
    L -->|切换| L
    L -->|确认| R[阅读短信]
    R -->|返回| L
    L -->|返回| H
    L -->|选重看入口| W[重放生日欢迎动画]
    W -->|结束/确认| L
~~~

生日欢迎和信箱仪式为**独立标记**，不要共用一个布尔值。3–5封正文仍由产品作者制作，公开仓库使用占位信件，不可捏造写成真实私人信件。星星视觉分档：0/1–25/26–50/51+；准确数字仍单独显示。

## 5. 时钟与昼夜天气

~~~mermaid
flowchart TD
    Power[上电] --> Noon[时间默认12:00]
    Noon --> InitWeather[本次启动按12:00白天时段抽取一次天气]
    InitWeather --> Home[直接进入猫咪房间，不强迫校时]
    Home --> T{用户进入时钟并主动校准?}
    T -->|是| Set[通过返回/切换/确认设置24小时 HH:MM]
    T -->|否| Free[保持从12:00开始的设备时间]
    Set --> Run[从新设时间走时]
    Free --> Run
    Run --> Period{设备时间到06:00/18:00}
    Period -->|06:00| Day[白天+重新抽白天天气]
    Period -->|18:00| Night[夜晚+重新抽夜间天气]
~~~

- 全断电失去真实时间时，不显示00:00或--:--，重新从中午12:00开始；并非承诺真实北京时间准确。
- 冷启动的12:00对应白天，**先初始化一次当期天气**，此后同一时段不因重绘/进入菜单反复掷天气；天气概率原方案80%晴、10%云、9%雨、1%特殊，但**白天特殊档处理待定**，不能自行指定其显示结果。
- 可以靠RTC/休眠计时使通电中走时，具体漂移、设备长期低功耗时的推进由硬件验证。
- 设备时钟不应用来判断专注是否自然完成：改钟不应使一段专注瞬间完成或发奖。

## 6. 待补齐的边界

1. 调暗10分钟后首按键同时正常操作还是先只恢复亮度？已经明确的是**熄屏后首键只唤醒**。
2. 时钟查看页校准入口及取消保存微交互、分钟是否逐位设置；已确认**三键足够**。
3. 退出确认页具体黑白文字及默认焦点；不得含自动结束。
4. 欢迎动画标记的写入点（建议确认祝福后持久化）、重看入口在信箱列表中的呈现。
5. 阅读信件页面是否适用10/60分钟闲置规则。
6. 手动校时跨06/18时天气如何刷新，以及掉电后当前时段天气是否保留。
7. 单色OLED低分辨率下挂钟大小、显示优先级和被数字遮挡后的行为。
